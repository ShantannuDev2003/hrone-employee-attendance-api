# REVIEW.md

List every defect you found in the starter `app/main.py` (helpers and endpoints). For each one:

| # | Where (function / line) | What is wrong | How you'd notice it (test, input, or symptom) | How you fixed it |
|---|---|---|---|---|
| 1 | `compute_late_minutes` (lines 33-37) | Incorrect grace period boundary check (`minutes > 10` returns 0 for 10m 1s because `int(601/60) == 10`), timezone naive hour replacement, and inability to handle overnight shift start times. | Shift 09:30, punch-in at 09:40:01 IST. Starter computes `minutes = 10`, fails `10 > 10`, returning 0 instead of 10. | Converted `punch_in` to IST, determined exact shift start datetime for the attendance date, and checked if elapsed seconds strictly exceed 600. If late, return `diff_seconds // 60`. |
| 2 | `compute_work_hours` (lines 40-41) | Uses Python's built-in `round()`, which applies Banker's rounding (round half to even) and float precision inaccuracies, violating Rule R4 (half-up rounding). Also ignores instant truncation (R1). | A duration of 9540 seconds / 3600 = 2.65, or float rounding cases like 2.675 where `round(2.675, 2)` produces 2.67 instead of 2.68. | Truncated instants to whole seconds first. Computed `(punch_out - punch_in).total_seconds() / 3600` via `Decimal` with `ROUND_HALF_UP` to 2 decimal places. |
| 3 | `compute_overtime` (lines 44-47) | Missing 30-minute minimum threshold (counts any positive minutes); incorrectly calculates shift end on the attendance date instead of the next calendar day for overnight shifts; raises `TypeError` subtracting naive and aware datetimes. | Shift 09:30-18:30, punch-out at 18:40 (10 min overtime). Starter returns 10 instead of 0 (threshold < 30). For overnight 22:00-06:00, calculates shift end 24h too early, giving ~1440 extra minutes. | Added 24-hour offset for overnight shifts (`shift_end <= shift_start`). Computed floor minutes between shift end and punch-out; returned `minutes if minutes >= 30 else 0`. Handled timezones uniformly. |
| 4 | `POST /attendance/punch-in` (lines 102-103) | Computes attendance date via `ts.date().isoformat()` using system local time, failing Rule R1 for overnight shifts where a punch-in before `shift_end` IST belongs to the previous calendar day. | Overnight shift 22:00-06:00, punch-in at 05:30 IST on 2026-07-07. Starter assigns date `2026-07-07` instead of `2026-07-06`. | Implemented `get_attendance_date` to check if `shift_end <= shift_start` and punch-in IST time < `shift_end`, decrementing calendar date by 1 day. |
| 5 | `POST /attendance/punch-in` & `POST /employees` (lines 79-83, 104-118) | Check-then-insert race condition (`find_one` followed by `insert_one`). Parallel identical requests both pass `find_one` and attempt insertion, causing unhandled `DuplicateKeyError` and returning 500 instead of 409. | 20 parallel punch-ins or employee creations with identical identifiers. | Created unique indexes on `employees.emp_code` and `attendance_logs.(emp_code, date)`. Caught `pymongo.errors.DuplicateKeyError` and raised clean `HTTPException(409)`. |
| 6 | `POST /attendance/punch-in` (line 101) | Does not verify employee existence. If `db.employees.find_one(...)` returns `None`, line 113 throws `TypeError: 'NoneType' object is not subscriptable`, causing an unhandled 500 error instead of 404. | `POST /attendance/punch-in` with `{"emp_code": "NONEXISTENT"}`. | Added explicit check: if `emp is None`, raise `HTTPException(status_code=404, detail="Employee not found")`. |
| 7 | `POST /attendance/punch-in` & `GET /attendance` (lines 119-120, 149) | Leaks internal MongoDB `_id` as `id` string in response dict. Contract states `_id` is strictly internal and attendance records have no ID. | Calling `POST /attendance/punch-in` returns an `"id"` field in the response JSON. | Removed `id` field injection and ensured `_id` is never returned in any response. |
| 8 | `GET /employees` (lines 93-95) | Wrong pagination offset: `skip = page * page_size` skips items 1-20 on `page=1`. Total count uses `count_documents({})`, ignoring the active department filter. Lacks sorting by `emp_code`. | `GET /employees?department=Engineering&page=1&page_size=10` skips the first 10 engineering employees; `total` reports total count of all departments. | Changed offset to `(page - 1) * page_size`, sorted cursor by `emp_code` ascending, and set `total = db.employees.count_documents(q)`. Enforced `page >= 1` and `1 <= page_size <= 100`. |
| 9 | `GET /attendance` (lines 144-147) | Loads the entire collection into memory with `list(db.attendance_logs.find(q))` and sorts in Python, causing OOM and severe latency at 100,000 documents. Omits secondary sort by `emp_code` ASC. | Running `GET /attendance` against 100k documents causes timeout/high memory usage and fails `COLLSCAN` explain checks. | Delegated filtering, compound sorting `[("date", -1), ("emp_code", 1)]`, `skip`, and `limit` to MongoDB cursor backed by compound index. |
| 10 | `GET /attendance` (lines 136-141) | Missing date range validation. If `date_from > date_to`, queries Mongo with impossible filter and returns empty list instead of HTTP 422. | `GET /attendance?date_from=2026-07-10&date_to=2026-07-01` returns 200 with empty list. | Added validation checking if `date_from and date_to and date_from > date_to`, raising `HTTPException(422)`. |
| 11 | `GET /health` (lines 72-74) | Dummy readiness probe returning hardcoded `{"status": "ok"}` 200 without checking if MongoDB is alive. | Stopped MongoDB server; `GET /health` continued returning 200 instead of 503. | Added `db.command("ping")`. Returned `{"status": "ok"}` on success, or raised `HTTPException(503)` if ping fails. |
| 12 | Instants representation & validation (lines 65, 82, 102) | Accepts arbitrary int for `punched_at` without validating epoch millisecond range (rejecting seconds < 10^11, floats, bools, strings with 422). `created_at` in `POST /employees` returned as ISO string instead of epoch ms. | Passing `punched_at: 1783312500` (seconds) or `true` accepted instead of returning 422; `created_at` returned as string. | Implemented custom `EpochMillis` Pydantic type with strict bounds and type checks (422 on failure). Converted datetimes to epoch milliseconds at API boundaries. |
| 13 | `POST /employees` (lines 58-59) | Lacks validation that `shift_start != shift_end`. Contract requires shift start and shift end to differ, returning 422 if equal. | `POST /employees` with `shift_start="09:00"` and `shift_end="09:00"` successfully created employee. | Added model validator in `EmployeeCreate` verifying `shift_start != shift_end`, raising 422 if equal. |
| 14 | Missing startup index creation | Starter creates no indexes. Database starts with only default `_id` index, failing unique constraints and causing COLLSCAN on list/analytics queries. | Queries on 100k docs execute COLLSCAN; concurrent writes allow duplicates. | Configured FastAPI `lifespan` handler to idempotently create all required unique and query indexes on startup. |

### Things checked and judged fine
- `IST = timezone(timedelta(hours=5, minutes=30))` is the correct offset for Indian Standard Time.
- Default shift times `09:30` and `18:30` correctly mirror the OpenAPI specification defaults.
- Pydantic models follow standard FastAPI idioms and field naming conventions.
